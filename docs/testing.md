# 테스트 운영

테스트는 사용자가 매번 실행하기보다 다음 채팅 세션이나 에이전트가 DB·서버·의존성을 수정할 때 회귀를 확인하기 위해 저장합니다. 새 테스트와 fixture는 모두 `tests/` 안에 둡니다. `.gitignore`의 tests 제외를 해제했고 Docker 컨텍스트에는 포함하지 않습니다.

```sh
bun install --frozen-lockfile
bun test tests/
bun run build
git diff --check
```

`bun run test`도 같은 테스트를 실행합니다. 별도 테스트 프레임워크 설치 없이 Bun test를 사용합니다. `jsconfig.json`의 checkJs는 false이고 타입 검사·lint 도구는 도입되어 있지 않으므로 빌드 통과를 타입 검사 통과로 표현하지 않습니다.

## 구성과 검증 내용

| 파일 | 검증 |
| --- | --- |
| `tests/db-lifecycle.test.js` | 20개 동시 인증 읽기, 읽기 후 컬렉션 쓰기, 연결 객체 동일성, 401 오류 이후 연결 유지, 공개 이미지·다운로드·Sharp 리사이즈, 로그아웃 격리, SIGINT/SIGTERM 종료, 비동기 요청 대기 중 다른 요청 완료와 정상 종료 |
| `tests/startup.test.js` | 미설치 503 → 설치 후 첫 요청, DB 미존재 시 생성 방지, 포트 충돌 시 연결 정리, 손상 DB 초기화 실패 후 재연결 |
| `tests/client-store.test.js` | Pinia 업데이트 후 실제 인증 스토어 설정·갱신·정리 및 에셋 페이지 설정 |
| `tests/fixtures/` | 임시 schema·이미지 생성, 별도 프로세스의 신호·시작 경계 검증 |

실제 `resource/seed.sql`로 OS 임시 디렉토리에 DB를 만들고 테스트 전용 JWT secret·계정·PNG를 사용합니다. `DATA_PATH`는 서버 import 이전에 임시 경로로 지정하며 HTTP 서버는 127.0.0.1의 임의 포트로 엽니다. 종료 후 임시 파일을 삭제합니다. 신호 테스트와 초기화 실패는 자식 프로세스로 격리하고 타임아웃 시 정리합니다. 운영 설치 명령을 실행하거나 운영 data를 복사하지 않습니다.

DB 수명 테스트는 한 서버를 공유하고 마지막 테스트에서 종료하므로 해당 파일에 `.concurrent`를 적용하지 않습니다. 마지막 테스트의 지연 경로는 테스트 중 server.reload로만 등록하고 프로덕션 라우트에 추가하지 않습니다.

## 결과 (2026-10-22)

- Bun 1.4.3, macOS 환경에서 테스트 **10개 통과, 실패 0개**.
- 실제 API의 읽기·쓰기·로그아웃·공개 파일 처리와 정상 종료 검증.
- 전체 서버·클라이언트 production 빌드 통과.
- frozen lockfile 설치 및 문서 상대 링크·diff 형식 검증.

처음 제한된 샌드박스에서는 포트 0의 listen이 EADDRINUSE로 실패했습니다. 로컬 리스닝을 허용한 실행에서는 통과했습니다. 같은 오류가 나면 실제 포트 충돌과 실행 환경의 소켓 제한을 구분합니다.

전체 브라우저 로그인·업로드·편집기 조작, Docker 이미지 빌드·실행, 운영 데이터의 성능·장시간 부하 테스트는 검증 범위 밖입니다. 특히 Pinia/concurrently 메이저 업데이트의 브라우저 UI 및 개발 서버 수동 검증은 배포 전 추가 확인 지점입니다. 이번 테스트는 속도 향상 수치를 보장하지 않고 연결 재사용과 기능 회귀를 확인합니다.

## 2026-10-23 추가 검증

`tests/vite-config.test.js`에 Bun 자동 .env 로딩 없이 Vite 개발 포트·프록시 값을 읽는 회귀 테스트를 추가했습니다. 포트 처리 단순화에 맞춰 별도 오류 메시지 테스트는 제거했으며, 환경 파일 로딩 테스트 1개가 통과했습니다. 앞선 수정에서는 전체 빌드도 통과했습니다. 별도 임시 환경에서 `bun run dev`의 Vite HTML 응답과 백엔드 프록시 응답도 확인했습니다. 브라우저 로그인·업로드 UI 검증은 여전히 별도 범위입니다.
